# Cross-workspace authorization security audit

## Executive summary

No exploitable cross-tenant authorization or metadata-disclosure finding remained after
the contract-v95 rollout. The review verified organization-bounded OAuth consent,
resource-owner authorization for writes, filtered realtime fan-out and cursor semantics,
and non-disclosing failures for excluded mission/objective references. PostgreSQL runtime
execution remains an unverified release gate in this environment; this is a validation
limitation, not evidence of a PostgreSQL-specific vulnerability.

## Surfaces reviewed

- Session and token authentication build one immutable `authorizedWorkspaces` snapshot,
  bounded to one selected organization and intersected with live memberships.
- OAuth approval, authorization-code exchange, single-workspace and all-workspaces token
  consent, revocation, and cross-organization rejection.
- Mission/objective UUID and display-id lookup, project and integration mutations,
  webhook subscription ownership, uploads/stored objects, execution targets and worktrees.
- Realtime catch-up reads, live broadcast filtering, authorization-change reconnects,
  high-water cursor behavior, and result/workspace labeling.
- CLI/MCP/REST contract declarations and the production ambient-workspace inventory.

## Findings

### Informational: PostgreSQL execution was unavailable locally

Evidence: `yarn test:conformance` completed all 31 SQLite tests successfully, but
`TEST_DATABASE_URL` was unset and access to `/var/run/docker.sock` was denied, so the
suite reported each PostgreSQL battery as skipped.

Impact: dialect parity is supported by mirrored migrations and shared batteries but was
not dynamically re-proven on this host. This does not widen authorization at runtime;
it leaves a release-validation gap.

Remediation: run `yarn test:conformance` in CI or on a host with `TEST_DATABASE_URL` (or
an available Docker daemon) before release and require the PostgreSQL battery to pass.

## Positive controls verified

- The AST scoping guard rejects every production ambient `getActiveWorkspace*` and
  `WORKSPACE.*` read outside the centralized compatibility definitions in `backend/db.ts`.
- Excluded workspace resources return generic `404` responses without tenant labels;
  genuine in-scope display-id ambiguity returns `409`.
- Token consent never grants membership: authorization is the consent allowlist (or
  organization-bound all-workspaces choice) intersected with current active membership.
- Realtime reads and broadcasts filter per authorized workspace and advance cursors over
  hidden global gaps without transmitting hidden change records.
- Parentless writes fail closed when their target workspace is omitted or ambiguous;
  entity writes derive the owning workspace before permission checks and attribution.
- Focused auth, OAuth, token, MCP, addressing, and realtime tests passed, as did complete
  typechecking and Local/Cloud production builds.

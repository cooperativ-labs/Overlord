## For Users

### Requirements

- Overlord CLI (`ovld`) on `PATH`. See the Overlord docs / Settings → Agents & MCP.
- Antigravity CLI (`agy`) on `PATH` for Overlord-launched sessions and plugin enablement. The lifecycle hooks need agy **1.5.4 or later** (the release that adds `hookEventName`, `cwd` and `toolCall.id` to hook input); `ovld agent-setup antigravity` and `ovld doctor` warn when `agy` is older. Run `agy update`.
- `bash` for the hook scripts.
- `MISSION_ID`, `OVERLORD_MISSION_ID` and `OVERLORD_OBJECTIVE_ID` are exported automatically when an Antigravity session is launched from Overlord. The hooks act only in such a session.

### Install

From an OpenOverlord checkout:

```bash
ovld agent-setup antigravity
```

This copies the managed plugin files to `~/.gemini/config/plugins/overlord`, the global plugin directory that Antigravity (CLI, app and IDE) loads plugins from, and the same place `agy plugin install` stages a plugin. `agy` picks it up on next startup and registers its skills, MCP server and hooks (`/hooks` lists them).

Earlier connector versions installed to `~/.gemini/antigravity-cli/plugins/overlord`, which current `agy` releases do not scan. Re-running `ovld agent-setup antigravity` moves an existing install: files the earlier install wrote and you have not edited are removed from the old location, while edited files are left in place and named in the output. `ovld doctor` reports an install that is still at the old location, and any files in the plugin directory that Overlord does not manage (Antigravity loads everything in a plugin's folder, so a leftover skill from an older hand-installed copy still loads).

Re-run safely any time the connector contract version changes:

```bash
ovld agent-setup antigravity
ovld doctor
```

### Permission warmup

Antigravity may still prompt once for `ovld protocol` approval on first use. Run this inside an Antigravity session and approve the prefix when prompted:

```bash
ovld protocol help
```

### Namespaced components

Inside Antigravity the plugin surfaces as:

- skills → `overlord-mission`, `attach`, `connect`, `load`, `create`, `prompt`, `discuss-objective`, `add-objectives`, `record-work` (each markdown skill also auto-registers as a `/<name>` slash command)
- MCP server → `overlord`
- hooks → the `overlord` group in `hooks.json`: `PreInvocation`, `PostToolUse`, `Stop`

Prompts generated by the runner should reference these names in bundle instruction mode.

## For Developers

### Overlord layer map

This connector is intentionally reviewable against the four connector layers in `connectors/README.md`:

- Connector Core: `../../core/overlord-mission/SKILL.md` and its `reference/` files carry the durable attach, update, ask, and deliver workflow.
- Connector Plugins: `skills/overlord-mission/SKILL.md`, `hooks.json`, and `scripts/` extend the core for Antigravity.
- Plugin Adapters: `plugin.json` declares the Antigravity-native plugin package; `mcp_config.json` wires the MCP bridge.
- Prompt Wrappers: `prompt-wrapper.md` describes the launch-time prompt shape for Antigravity.

### What ships

- `plugin.json` — Antigravity plugin manifest, kept to the documented schema (`$schema`, `name`, `displayName`, `version`, `description`, `logo`, `suggestedPrompts`, `author`, `homepage`, `repository`, `license`, `keywords`); the schema rejects unknown top-level fields.
- `assets/logo.png` — the plugin logo `plugin.json` points at.
- `skills/overlord-mission/SKILL.md` — Antigravity adapter template with a `<!-- @connector-core -->` marker; setup interpolates shared core content at install time.
- `skills/attach.md`, `skills/connect.md`, `skills/load.md`, `skills/create.md`, `skills/prompt.md`, `skills/discuss-objective.md`, `skills/add-objectives.md`, `skills/record-work.md` — one skill per protocol operation; Antigravity auto-registers each as a `/<name>` slash command.
- `hooks.json` — one `overlord` hook group with three command hooks (see the mapping below). Plugin hooks run with the plugin folder as their working directory, so the commands are relative paths (`./hooks/…`), never `${PLUGIN_ROOT}`.
- `hooks/overlord-pre-invocation.sh`, `hooks/overlord-stop.sh` — thin shell hooks that gate on the launch environment and hand the native payload to `ovld protocol hook-event` / `ovld agent-session inbox`.
- `hooks/overlord-post-tool-use.sh` — **generated**: the core capture callback `connectors/core/scripts/capture-change-hook.sh`, rendered at setup with the adapter key. There is no copy in this directory.
- `codec/antigravity.codec.yaml`, `codec/antigravity.decision-codec.yaml` — the connector-owned event and PreToolUse decision dialects, compiled into the CLI by `yarn connectors:capabilities`.
- `harness-capabilities.yaml` + `fixtures/` — the fixture-backed capability descriptor; `CAPABILITIES.md` is generated from it.
- `mcp_config.json` + `scripts/overlord-mcp.mjs` — MCP bridge to common `ovld protocol` operations (requires `ovld` on `PATH` and valid credentials when talking to a live server). Antigravity namespaces the server as `overlord_overlord`. The shim is **generated**: it is rendered from `connectors/core/scripts/overlord-mcp.mjs` at setup time with the adapter key substituted, and there is no copy in this directory to edit.
- `conformance-manifest.yaml` — connector conformance declaration for the Overlord contract.
- `prompt-wrapper.md` — Antigravity launch guidance.

### Validation

`yarn connectors:antigravity:check` (part of `yarn connectors:check`) renders the managed files into a scratch plugin root, checks `plugin.json` and `mcp_config.json` against the documented plugin schema, and then runs `agy plugin validate --strict --json` on the result. The `agy` step is skipped when `agy` is not on `PATH` (set `OVERLORD_AGY_BIN` to use another binary); an `agy` too old for `--strict` runs the basic validator and says so.

The shared Connector Core source lives at `connectors/core/overlord-mission`. `ovld agent-setup antigravity` interpolates that core into the adapter skill template and installs core reference files so the runtime package is self-contained.

### Omissions

- **No model or effort flag at launch.** Antigravity selects the model internally, so Overlord passes neither. Deliberate.
- **No `commands/` directory.** Antigravity auto-registers each `skills/*.md` as a `/<name>` slash command, so a separate commands surface would be redundant. Deliberate.
- **No `PreToolUse` decision hook.** The decision codec pins the exact response bytes, but no launch creates a session channel today, so Antigravity's own permission flow stays the only authority. `decide.*` are `not-implemented`.
- **No `SessionStart` or `PostInvocation` hooks.** Nothing in Overlord consumes them yet.
- **No chat-started binding.** Antigravity exports no conversation id to tool processes, so `ovld protocol attach` run by the agent cannot index its conversation; the hooks only act in sessions Overlord launched.

See the [adapter capability matrix](../../README.md#adapter-capability-matrix) for how this compares across adapters.

### Notes on the Antigravity hook mapping

Antigravity's hook contract (https://antigravity.google/docs/hooks) differs from Claude's in
three ways that shape the mapping: hook input is camelCase JSON, the submitted prompt is the
`lastUserInput` field rather than a prompt event, and Stop continues on `decision: "continue"`.
Every hook prints one JSON object (`{}` at minimum) when bound, and nothing at all when unbound.
A failing hook is logged and ignored by agy (fail-open), so no failure here can block or approve
a tool call.

| Antigravity event | Matcher / input | Script | Overlord path | Capability |
| --- | --- | --- | --- | --- |
| `PreInvocation` | `lastUserInput`, `conversationId` | `hooks/overlord-pre-invocation.sh` | `ovld protocol hook-event --hook-type UserPromptSubmit` records a follow-up; with a session channel, `ovld agent-session inbox` answers `{"injectSteps":[{"userMessage":…}]}` | `observe.prompt` ✅, `inject.nextTurn` 🚧 (channel not wired) |
| `PostToolUse` | `write_to_file\|replace_file_content\|multi_replace_file_content\|run_command` | `hooks/overlord-post-tool-use.sh` (core) | `ovld protocol capture-change --agent antigravity` | `observe.fileEdit` ✅, `observe.toolResult` ✅ |
| `Stop` | `continuation_active`, `fullyIdle` | `hooks/overlord-stop.sh` | with a session channel, inbox first; otherwise `hook-event --hook-type Stop` answers the delivery reminder `{"decision":"continue","reason":…}` | `inject.turnBoundary` ✅ |
| `PreToolUse` | — | not registered | decision codec only (`auto_approve` / `deny` / silence) | `decide.*` 🚧 |

Details:

- **Binding.** `conversationId` is the native session id. It is a correlation alias that
  `hook-event` records as the session's external id; the launch environment is the authority.
  The scripts check `OVERLORD_MISSION_ID`/`MISSION_ID`/`OVERLORD_OBJECTIVE_ID` before reading
  stdin or spawning anything.
- **Working directory.** agy runs plugin hooks in the plugin folder. `hook-event` locates the
  session-key cache from the payload's `cwd` (or the first `workspacePaths` entry), and
  `capture-change` relativizes paths against the same root.
- **Prompt capture.** `PreInvocation` fires before every model call, repeating the same
  `lastUserInput`. `hook-event` records a prompt only when it differs from the last one recorded
  for the conversation (a hash is kept under the global data dir), and the first prompt of a
  launched session (turn 0, the launch prompt) is skipped as for every adapter. The cost is one
  `ovld` spawn per model call in a launched session.
- **File capture.** The codec reads `toolCall.name`, `toolCall.args.TargetFile` and `error`.
  `error` is "empty if successful", so an empty or absent `error` is `ok` (codec field
  `outcomeErrorPath`). Only an `ok` edit records `declared_edit` evidence; a failed edit records
  `outcome_partial`; `run_command` records `shell_activity_unverified`.
- **Stop.** The delivery reminder is shown once per session and objective, never while
  `continuation_active` is true (this stop already follows a continuation) and never while
  `fullyIdle` is false (background work is still running). agy also caps consecutive
  continuations itself.
- **Older agy.** Before 1.5.4 payloads carry no `hookEventName`. The hooks still run: Stop and
  PreInvocation pass the hook type explicitly, while file capture matches no codec rule and
  records only callback health.

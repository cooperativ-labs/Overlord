## For Users

### Requirements

- Overlord CLI (`ovld`) on `PATH`. See the Overlord docs / Settings → Agents & MCP.
- Antigravity CLI (`agy`) on `PATH` for Overlord-launched sessions and plugin enablement.
- `MISSION_ID` is exported automatically when an Antigravity session is launched from Overlord.

### Install

From an OpenOverlord checkout:

```bash
ovld agent-setup antigravity
```

This copies the managed plugin files to `~/.gemini/antigravity-cli/plugins/overlord` so `agy` picks it up automatically on next startup (Antigravity crawls its plugin directory and registers skills, hooks, and MCP servers into active memory).

Re-run safely any time the connector contract version changes:

```bash
ovld agent-setup antigravity
ovld doctor
```

### Permission warmup

Antigravity may still prompt once for `ovld protocol` approval on first use. Run this inside an Antigravity session and approve the prefix when prompted:

```bash
ovld protocol help
```

### Namespaced components

Inside Antigravity the plugin surfaces as:

- skills → `overlord-mission`, `attach`, `connect`, `load`, `create`, `prompt`, `discuss-objective`, `add-objectives`, `record-work` (each markdown skill also auto-registers as a `/<name>` slash command)
- MCP server → `overlord`

Prompts generated by the runner should reference these names in bundle instruction mode.

## For Developers

### Overlord layer map

This connector is intentionally reviewable against the four connector layers in `connectors/README.md`:

- Connector Core: `../../core/overlord-mission/SKILL.md` and its `reference/` files carry the durable attach, update, ask, and deliver workflow.
- Connector Plugins: `skills/overlord-mission/SKILL.md`, `hooks.json`, and `scripts/` extend the core for Antigravity.
- Plugin Adapters: `plugin.json` declares the Antigravity-native plugin package; `mcp_config.json` wires the MCP bridge.
- Prompt Wrappers: `prompt-wrapper.md` describes the launch-time prompt shape for Antigravity.

### What ships

- `plugin.json` — Antigravity plugin manifest (name, description, metadata).
- `skills/overlord-mission/SKILL.md` — Antigravity adapter template with a `<!-- @connector-core -->` marker; setup interpolates shared core content at install time.
- `skills/attach.md`, `skills/connect.md`, `skills/load.md`, `skills/create.md`, `skills/prompt.md`, `skills/discuss-objective.md`, `skills/add-objectives.md`, `skills/record-work.md` — one skill per protocol operation; Antigravity auto-registers each as a `/<name>` slash command.
- `hooks.json` — intentionally empty until a fixture-proven agent-session callback is installed.
- `mcp_config.json` + `scripts/overlord-mcp.mjs` — MCP bridge to common `ovld protocol` operations. The shim is **generated**: it is rendered from `connectors/core/scripts/overlord-mcp.mjs` at setup time with the adapter key substituted, and there is no copy in this directory to edit.
- `conformance-manifest.yaml` — connector conformance declaration for the Overlord contract.
- `prompt-wrapper.md` — Antigravity launch guidance.

The shared Connector Core source lives at `connectors/core/overlord-mission`. `ovld agent-setup antigravity` interpolates that core into the adapter skill template and installs core reference files so the runtime package is self-contained.

### Omissions

- **No model or effort flag at launch.** Antigravity selects the model internally, so Overlord passes neither. Deliberate.
- **No `commands/` directory.** Antigravity auto-registers each `skills/*.md` as a `/<name>` slash command, so a separate commands surface would be redundant. Deliberate.
- **No `PostToolUse` or `Stop` hooks.** Only follow-up and permission capture are mapped; whether Antigravity exposes the equivalent events is not yet established. Treat as open work.

See the [adapter capability matrix](../../README.md#adapter-capability-matrix) for how this compares across adapters.

### Native evidence status

The descriptor records Antigravity's first-party event schema and keeps decision capabilities
unimplemented until a real installed `agy` binary can exercise exact decision and timeout
behavior through the channel-scoped agent-session runtime. No mutation attribution is recorded:
the adapter has no fixture-proven completion hook.

No `Stop` hook or permission-rule file ships yet — Antigravity's pending-delivery check and any declarative auto-approval mechanism should be added once their concrete formats are confirmed, matching the "can be implemented after local MVP" note in `connectors/docs/05-connectors-and-agent-plugins.md`.
